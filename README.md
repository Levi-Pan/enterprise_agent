# 企业制度知识库

本地运行的公司文档问答工具。管理员上传 Word 后，原文件、正文段落和中文全文索引保存在 SQLite 中；员工在同一个服务上提问，系统检索相关段落后调用已配置的模型回答，并展示检索到的参考原文。

## 启动

现有项目已经有 `.venv` 和 `.env`。在项目目录的 PowerShell 中执行：

```powershell
& .\start_local.ps1
```

打开 <http://127.0.0.1:8000/>。停止服务按 Ctrl + C。

首次访问点击“没有账号？创建账号”，设置账号和至少 8 位密码。账号支持英文字母、数字、下划线、点、连字符和 @，不区分大小写。以后用同一账号登录，左侧显示自己的历史对话，默认打开最近一次对话。点击“新对话”创建另一段对话；点击历史标题查看原问题、回答和来源，也可以删除自己的对话。

升级到此版本后需要停止原服务并重新启动。升级前页面中的聊天没有保存到数据库，无法自动恢复；已经导入的公司文档会保留。

在新电脑上，先创建虚拟环境，安装依赖，再根据 `.env.example` 配置 `.env`：

```powershell
python -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 导入公司文档

1. 登录账号，打开左侧“公司知识库”。
2. 展开“管理员 · 导入和管理文档”。
3. 从本机 `.env` 复制 `ADMIN_API_TOKEN` 的值，填写并点击“验证”。员工查询不需要这个密钥。
4. 选择 `.docx` 文件，点击“导入知识库”。同名内容发生变化时，需要明确勾选“替换同名文档”。相同内容不会重复保存。
5. 导入后可以查看正文；所有连接这个服务的使用者查询的是同一份知识库。

管理员可以删除已保存文档。删除会同时清理正文和检索索引。密钥只保存在当前页面内存中，刷新后需要重新验证。

## 提问与来源

输入具体的制度问题，例如“代码规范对变量命名有什么要求？”。检索使用中文字符对、英文词和 SQLite FTS5 的 BM25 排序，属于关键词检索，第一版不包含语义向量检索。可以尝试使用文档中的关键词。

没有匹配到资料时会提示补充文档，且不调用模型。匹配到资料时，将所选段落提交给 `.env` 配置的模型服务生成回答。回答下方列出检索原文，点击展开可核实。模型输出仍可能有误；“检索到的参考原文”表示送给模型的资料，并非对回答正确性的自动认证。

每次提问独立处理，不传递历史对话。Word 正文及普通表格可以提取；图片、扫描件、页眉页脚、文本框及修订中的特殊内容尚不支持。段落编号用于定位，不是 Word 页码。

## 数据与配置

- 默认数据路径由项目绝对路径推导，保存到 `data/knowledge.db`，可用 `KNOWLEDGE_DB_PATH` 指定新的绝对路径。
- 默认上传上限 10 MiB，ZIP 解压总大小上限 30 MiB；可在 `.env` 配置 `DOCUMENT_UPLOAD_MAX_BYTES` 和 `DOCUMENT_XML_MAX_BYTES`。
- 原文件也保存在数据库中。服务重启后无需重新导入。
- 账号、登录会话、对话和问答记录也保存在同一个 `data/knowledge.db`，分别对应 `users`、`sessions`、`conversations`、`chat_turns` 表。文档由全公司共享；对话按 `user_id` 隔离，每次读取、续写和删除都检查所属账号。没有为每个员工建立单独的数据库文件。
- 密码保存为随机盐加 PBKDF2 摘要，登录凭据使用 HttpOnly Cookie，数据库只保存凭据摘要。退出登录会撤销当前凭据。默认登录有效期为 7 天，连续登录失败会暂时限制重试。
- 问题先保存，随后保存回答、来源和完成状态；回答失败的记录也能查看。历史来源保存的是当时检索到的原文快照。对话保存与模型记忆是两件事，目前每次提问仍独立检索，模型不会自动读取上轮回答。
- 本地默认允许注册，可用 `ALLOW_SELF_REGISTRATION=false` 关闭新账号注册；已有账号仍能登录。部署 HTTPS 时设置 `SESSION_COOKIE_SECURE=true`。普通账号不会获得上传和删除公司文档的管理权限，管理仍需独立密钥。
- `.env`、数据库和运行日志均被 Git 忽略。备份时先停止服务，再备份整个 `data` 目录和单独保管的配置。
- SQLite 适合当前单机版本，多进程读取与少量并发写入。将来多服务器部署时需要迁移到集中式数据库。

## 全公司访问

当前启动脚本只监听 `127.0.0.1`，供本机验证。它尚未部署为全公司可访问的服务。

准备好公司服务器后，把项目、配置和知识库迁移到同一台服务器，安装依赖，运行：

```powershell
& .\.venv\Scripts\python.exe -m uvicorn app.api_run:app --host 0.0.0.0 --port 8000
```

员工通过 `http://服务器内网IP:8000/` 访问，前端会自动连接同一台服务器的接口，不需要修改前端地址。服务器必须保持运行，网络需允许员工访问该端口。

目前已支持账号登录和个人聊天隔离，所有已登录员工共享公司知识库。尚未接入公司单点登录、部门文档权限、账号找回或人员管理后台。正式上线时按公司的网络与访问管理方式配置账号发放、HTTPS 和进程守护。

## 验证

```powershell
& .\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

测试使用隔离数据库和模拟模型，不调用实际付费接口，覆盖账号注册登录、凭据撤销、聊天持久化、跨账号访问拦截，以及文档权限、重复导入、替换删除、并发写入、资料检索和超限文件处理。

## 真实 Agent 问答评测

`app/evaluate_agent_run.py` 使用 `.env` 中配置的真实模型，通过 Responses API 工具调用自主提问并评审回答。无需先启动网页服务器：它使用与网页相同的 FastAPI `/chat` 接口，在本进程中执行。

默认使用合成文档，直接运行该入口文件即可。评测会产生真实 API 调用费用。使用公司文档时，命令如下；`--company-data` 表示本轮已明确授权将抽样原文、问题、回答及检索片段发送给配置的模型服务：

```powershell
& "D:\code Python\enterprise_agent\.venv\Scripts\python.exe" "D:\code Python\enterprise_agent\app\evaluate_agent_run.py" --company-data --questions 6
```

正式 SQLite 库通过只读连接复制到临时库，评测不导入、删除或更新正式文档。每道问题独立处理。报告保存在项目 `data/evaluations` 中：HTML 用浏览器打开，JSON 保留问题、真实回答、检索原文、响应时间、模型使用量和自动评审。若中途失败，报告保留已经完成的结果。

默认六类测试依次为具体章节、口语问法、未规定数值、跨章节比较、无关问题和全文总结。模型可能把题目类别标错，需要人工核查。回答和评审使用相同模型，自动评分不能作为独立准确率或正式验收结论。全文总结另外检查来源块数量，覆盖不足时不能判定完整通过。
